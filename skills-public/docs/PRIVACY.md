# 기자 개인정보 보호 원칙 (PII Protection)

크랩피치 스킬은 기자를 **잠재적 협업 상대**로 존중한다. 공개된 직무 연락처라도
화면에 실명·이메일·연락처를 **함부로 노출하지 않는다.**

## 절대 규칙

1. **화면/출력 비노출** — 기자 **실명, 이메일, 전화번호**는 채팅 응답·리스트·표·미리보기
   어디에도 그대로 출력하지 않는다. 대신 **익명 코드**(예: `기자 #A3F1`) + **매체명** + **beat** +
   **신뢰도**만 노출한다.
2. **발송 시점에만 실명/이메일 사용** — 실제 이메일 주소와 수신자 실명은 **메일을 실제로
   보낼 때** Gmail의 수신자(To)와 본문 인사말(예: "○○ 기자님")에만 주입한다.
   그 외 어떤 단계에서도 실명/이메일을 텍스트로 노출하지 않는다.
3. **보낸 기록** — 이미 발송된 메일(Gmail 보낸편지함 / `언론홍보` 라벨)에는 당연히 실명·이메일이
   본문·헤더에 남는다. 그러나 그것은 **발송 시점의 실제 메일**이며, 앱/스킬 화면에서 기자 목록을
   다시 보여줄 때는 여전히 익명 코드로만 표시한다.
4. **로그·요약 금지** — 매칭 이유, 성과 리포트, 대화 요약 등에도 실명·이메일을 넣지 않는다.
   ("`기자 #A3F1`(지디넷·핀테크)에게 발송" 처럼 코드로 지칭.)

## 익명 코드 규칙

- 같은 기자는 항상 같은 코드로 표시(연락처 id 기반의 안정적 비가역 코드).
- 코드로 매체·beat·적합도는 파악되지만, 코드만으로 실명/이메일을 역추적할 수 없다.

## 예시

- ❌ `이도원(leespot@zdnet.co.kr) 87점`
- ✅ `기자 #A3F1 · 지디넷코리아 · 플랫폼/핀테크 · 신뢰도 high · 87점`
- ✅ 발송 메일 본문(Gmail): `이도원 기자님, 안녕하세요…` ← 실제 발송 시점에만
