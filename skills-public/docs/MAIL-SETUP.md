# 발신 메일 설정 (SMTP)

Gmail 연결이 어렵거나 회사 메일로 보내야 할 때 쓰는 경로다. 제공자를 가리지 않는다 —
Gmail·네이버·다음·아웃룩·회사 메일 모두 붙는다.

> **Gmail 라벨 워크플로우([GMAIL-SETUP.md](./GMAIL-SETUP.md))는 Agency 플랜 전용이다.**
> 다른 플랜은 이 문서의 SMTP 경로를 쓴다.

## 두 경로의 차이

| | SMTP 직접 발송 | Gmail 초안 생성 |
|---|---|---|
| 플랜 | **전 플랜** | **Agency 전용** |
| 결과 | 기자 메일함으로 **즉시 발송** | Gmail `언론홍보` 라벨에 **초안** |
| 되돌리기 | **불가능** | 발송 전이라 가능 |
| 준비물 | 이메일 + 비밀번호 | Google 계정 연결(OAuth) |
| 제공자 | 무관 | Gmail 전용 |

**규칙은 같다.** 파일럿 승인·수신거부 재대조·7일 쿨다운·표현 규정·캠페인당 상한·월 한도를
두 경로 모두 똑같이 통과한다. 전송 수단이 다를 뿐이고, **잠긴 것은 발송 기능이 아니라
수단 하나다.**

Gmail 경로만 Agency로 묶은 이유는 비용 구조가 다르기 때문이다. Gmail API는 제한 스코프라
CrabPitch가 Google 검수를 받고 유지해야 하며, 미검수 상태에서는 연결 사용자 수에 상한이
걸린다. SMTP에는 그런 제약이 없다.

Agency 플랜에서 둘 다 연결돼 있으면 **되돌릴 수 있는 쪽(Gmail 초안)이 기본**이다. SMTP로
보내려면 캠페인 화면에서 명시적으로 고르고 확인 창을 한 번 더 거친다.

## 설정 절차

CrabPitch 웹앱 → **설정** → **발신 메일 (SMTP)**

입력할 것은 **이메일과 비밀번호 둘뿐**이다. 서버 주소·포트·보안 방식은 이메일 도메인으로
자동 판별한다. 저장하면 곧바로 연결 테스트가 돌고, 실패하면 무엇을 고쳐야 하는지 알려 준다.

### Gmail

1. Google 계정에서 **2단계 인증**을 켠다 (앱 비밀번호는 2단계 인증이 켜져 있어야 발급된다)
2. https://myaccount.google.com/apppasswords 에서 **앱 비밀번호**를 발급받는다
3. 비밀번호 칸에 **앱 비밀번호**를 넣는다 — 계정 비밀번호를 넣으면 인증에 실패한다

### 네이버 · 다음(카카오)

메일 **환경설정 → IMAP/SMTP 사용**을 먼저 켠다. 기본값이 꺼져 있어서, 켜지 않으면 연결이
거부된다. 이때 나오는 오류는 주소 오타처럼 보이지만 원인이 다르다.

- 네이버: https://mail.naver.com/option/imap
- 다음: https://mail.daum.net/#/settings/imap

### 회사 메일

서버 주소를 자동으로 알아낼 수 없다. 관리자에게 SMTP 서버 주소와 포트를 확인한 뒤
**서버 직접 설정**을 펼쳐 입력한다. 관례상 `mail.도메인` 또는 `smtp.도메인`, 포트는
587(STARTTLS) 또는 465(SSL)다.

## MCP로 안내받기

Claude·ChatGPT 등에서 `crabpitch_mail_setup`을 부르면 현재 연결 상태와 제공자별 절차를
돌려준다. 이메일을 함께 주면 절차가 그 제공자로 좁혀진다.

> **이 도구는 비밀번호를 받지 않는다.** 입력 스키마에 자리가 없다. MCP 인자는 대화 기록에
> 남고, 그곳은 우리 DB보다 통제가 약하다. **에이전트에게 비밀번호를 불러 주지 마라** —
> 대신 받아 입력해 주겠다는 제안도 거절해야 한다. 입력은 반드시 웹 설정 화면에서 직접 한다.

## 비밀번호는 어떻게 보관되나

- **AES-256-GCM으로 암호화**해서 저장한다. 발송하는 순간에만 복호화한다.
- 화면·API 어디로도 다시 나가지 않는다. 마스킹된 별표조차 내보내지 않는다 — 길이도 정보다.
- 해시가 아니라 암호화인 이유: SMTP 서버에 **원문을 넘겨야** 메일이 나간다. 대조만 하면 되는
  API 키와는 다른 문제다.

Gmail 앱 비밀번호는 IMAP까지 열려 있어 과거 메일 전부를 읽을 수 있다. 그래서 평문 저장은
선택지에 없고, 암호화 키가 설정돼 있지 않으면 저장 자체가 실패한다.

## 발송이 실패할 때

| 증상 | 원인 | 할 일 |
|---|---|---|
| 인증 실패 (Gmail) | 계정 비밀번호를 넣음 | 앱 비밀번호를 발급해 다시 입력 |
| 연결 거부 (네이버·다음) | SMTP 사용이 꺼져 있음 | 메일 환경설정에서 켜기 |
| 시간 초과 | 사내망·방화벽이 SMTP 포트를 막음 | 망 관리자에게 문의 |
| 인증서 오류 | 포트와 보안 방식 불일치 | 465/SSL, 587/STARTTLS로 맞추기 |

일부만 실패한 경우 **성공한 건만 발송으로 확정**되고 실패한 건은 초안으로 남는다.
고친 뒤 다시 보내면 된다. 인증·연결처럼 계정 자체의 문제는 첫 건에서 멈춘다 — 같은 오류를
수신자 수만큼 반복하지 않는다.

## 한 번에 몇 명까지

권장은 **한 번에 20명 이하**다. 금지선이 아니라 권장치이고, 필요하면 더 지정할 수 있다.
다만 동시에 많은 수에 보내면 수신 서버가 스팸으로 판정해 도메인 평판이 깎인다. 나눠 보내는
편이 도달률에 낫다.
