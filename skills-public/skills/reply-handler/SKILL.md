# 회신 응대 (reply-handler)

기자 회신은 관계의 시작이다. 빠르고 정확한 응대가 게재율을 좌우한다.
이 스킬은 Gmail **`언론홍보`** 라벨의 회신을 자동 분류하고 유형별 답장 초안을 만든다.

## ⛔ 개인정보 원칙
- 회신 목록·요약을 보여줄 때 기자 **실명·이메일을 노출하지 않는다.** `기자 #A3F1 · 지디넷` 처럼 코드로.
- 답장 초안 본문 인사말은 **"기자님"**으로. 실명은 **실제 회신 발송 시점**의 Gmail 본문에만 주입.

## 회신 수집 (Gmail MCP)
1. `mcp__Gmail__list_labels`로 `언론홍보` **라벨 ID** 조회 → `mcp__Gmail__search_threads`에 `label:{라벨ID}`로 미응답 스레드 수집(답장 알림 — `label:`은 표시명이 아닌 라벨 ID를 받는다).
2. `mcp__Gmail__get_thread` — 원문 파악 → 아래 7유형 분류.
3. 분류 후 `mcp__Gmail__label_thread` — `언론홍보/회신`·`언론홍보/인터뷰`·`언론홍보/수신거부` 재분류.
4. 유형별 `mcp__Gmail__create_draft`(`replyToMessageId`) 답장 초안 → 사용자 검토 후 발송.

**CrabPitch MCP 연결 시** 분류에 `crabpitch_classify`를 먼저 호출해도 된다(동일 7유형). 최종 발송·실명 주입은 Gmail에서만.

### 플랜 확인 (MCP 사용 시)
`crabpitch_classify`는 **MCP에서 유료 전용**이다. `crabpitch_status`의 `skills`에
`reply-handler`가 없으면 호출하지 말고, 아래 7유형 규칙으로 **직접 분류한다** — 분류 규칙
자체는 이 문서에 다 있으므로 무료 플랜에서도 응대는 그대로 할 수 있다.
회신 이력을 남기고 억제 리스트에 반영하려면 CrabPitch 웹앱을 쓰면 되고, 웹앱의 회신 응대는
무료 플랜에서도 열려 있다. 사용자에게 이 우회로를 함께 알린다.

## 7유형 분류
| 유형 | 신호 | 우선순위 | 액션 |
|---|---|---|---|
| ① 인터뷰 요청 | "인터뷰", "통화 가능", "일정" | 🔴 즉시 | 일정 3안 + 대표 연결, `언론홍보/인터뷰` |
| ② 자료 요청 | "고화질", "추가 자료", "매출 자료" | 🔴 즉시 | 요청 자료만 정확히 |
| ③ 확인 질문 | "맞나요", "근거", "수치" | 🟠 당일 | 팩트+근거 링크만 |
| ④ 게재 통보 | "기사 나갔", 링크 | 🟢 감사 | 감사 회신 + 성과 집계 |
| ⑤ 보류/거절 | "이번엔 어렵", "다음 기회" | 🟢 정중 | 감사 + 다음 소식 예고 |
| ⑥ 수신거부 | "수신거부", "그만", "빼주세요" | ⚫ 즉시 | 억제 리스트 등록 + 사과 없는 정중한 확인, `언론홍보/수신거부` |
| ⑦ 부정/컴플레인 | 사실오류 지적, 항의 | 🔴 신중 | 사실 확인 → 정정, 방어 금지 |

### ③ 확인 질문은 5가지로 갈린다
답의 성격이 완전히 다르므로 먼저 하위 유형을 판정한다.

| 하위 유형 | 예 | 답의 축 |
|---|---|---|
| 수치 검증 | "이 숫자 근거가?" | 집계 기준·시점·출처 |
| 경쟁사 비교 | "A사 대비 뭐가 다른가요" | 사실 차이만. 경쟁사 평가 금지 |
| 전략 의도 | "왜 지금인가요" | 결정 배경 |
| 향후 계획 | "다음 단계는" | 확정된 것만. 미확정은 미확정이라고 |
| 부정적 맥락 | "논란이 있던데" | **에스컬레이션.** 즉답하지 말고 사용자에게 넘긴다 |

답장 초안은 **3단 구성**으로 만든다: `공식 답변` → `쓸 수 있는 대체 표현` → `Do Not Say`.
마지막 칸이 핵심이다 — 하지 말아야 할 말을 미리 못 박아 둔다.

## 유형별 답장 톤(요지)
- **인터뷰**: 빠르게, 선택지(일정 3안) + 대표 연결.
- **자료**: 군더더기 없이 **약속한 것만.** 보낸 적 없는 자료를 링크로 채우지 않는다.
- **확인 질문**: 팩트 + 근거. 홍보 문구 금지. 부정적 맥락이면 즉답 금지.
- **게재**: 진심 어린 감사 1회 + 다음 관계. **사실오류가 있으면 정정 요청**을
  감정 없이 사실만 정리해 별도로 보낸다(언론중재법 영역은 아니며 법률 검토를 대체하지 않는다).
- **보류/거절**: 다음 소식 때 재접근해도 되는지 판단해 기록한다. "다음 기회에"는 재접근 가능,
  명시적 거절은 아니다.
- **수신거부(핵심)**: 변명·설득·사과 없이 즉시 수용 + **억제 리스트 등록 + `언론홍보/수신거부` 라벨**. 예)
  `기자님, 알겠습니다. 명단에서 즉시 제외했습니다. 좋은 하루 보내세요.`
- **컴플레인**: 방어·감정 금지. 사실 확인 → 정정/사과.

## 무회신 팔로업
회신이 없는 기자에게는 **7일 이후**에만 다시 접촉한다(쿨다운과 같은 간격).

- **새 정보가 없으면 팔로업하지 않는다.** 같은 내용을 다시 보내는 것은 스팸이다.
  서버가 원본과의 유사도를 검사해 재탕을 걸러낸다.
- "지난 메일을 못 보셨을 수도" 같은 재촉 표현은 쓰지 않는다.
- 이미 회신을 받은 기자는 팔로업 대상이 아니다 — 그 스레드에서 이어간다.

## 응대 스타일
존댓말·간결·담백. 이모지/과한 감탄사 금지. "감사합니다"는 진심으로 1회. 회신 끝에 다음 관계의 여지.

## 절대 하지 말 것
- 실명·이메일 화면 노출 · 수신거부 요청에 재발송·설득 · 사실오류에 방어 대응 · 인터뷰/자료 24h 초과 방치
- 부정적 맥락 질문에 현장에서 즉답 · 보낸 적 없는 자료를 약속 · 새 정보 없는 팔로업
