# 회신 응대 (reply-handler)

기자 회신은 관계의 시작이다. 빠르고 정확한 응대가 게재율을 좌우한다.
이 스킬은 Gmail **`언론홍보`** 라벨의 회신을 분류하고 유형별 답장 초안을 만든다.

> **규범 정본은 `convex/lib/replyClassifier.ts`다**(신호어·유형·하위 분류·초안 스캐폴드).
> 수신거부 억제 등록은 `convex/replies.ts`가 **서버에서 강제**한다.
> 값이 어긋나면 코드가 맞다. 코드를 고칠 때 이 문서를 같은 PR에서 갱신한다.

## 응대 3원칙

1. **속도** — 인터뷰·자료 요청은 당일(늦어도 2시간 내). 기자에게는 마감이 있다.
2. **정확** — 물어본 것만, 사실로. 모르면 "확인해 회신드리겠습니다"가 정답이다. **지어내지 않는다.**
3. **관계** — 이번에 안 써도 다음이 있다.

## ⛔ 개인정보 원칙

- 회신 목록·요약에 기자 **실명·이메일을 노출하지 않는다.** `기자 #A3F1 · ○○일보`처럼 코드로.
- 답장 초안 인사말은 **"기자님"**. 실명은 **실제 회신 발송 시점**의 Gmail 본문에만 주입한다.

## 회신 수집 (Gmail MCP)

1. `mcp__Gmail__list_labels`로 `언론홍보` **라벨 ID** 조회 → `mcp__Gmail__search_threads`에
   `label:{라벨ID}`로 미응답 스레드 수집(`label:`은 표시명이 아니라 라벨 ID를 받는다).
2. `mcp__Gmail__get_thread` — 원문 파악 → 아래 유형 분류.
3. `mcp__Gmail__label_thread` — `언론홍보/회신`·`언론홍보/인터뷰`·`언론홍보/수신거부` 재분류.
4. `mcp__Gmail__create_draft`(`replyToMessageId`) 답장 초안 → 사용자 검토 후 발송.

CrabPitch MCP 연결 시 `crabpitch_classify`를 먼저 호출해도 된다(동일 7유형).
최종 발송·실명 주입은 Gmail에서만 한다.

## 7유형 분류

| 유형 | 신호 | 우선순위 | 액션 |
|---|---|---|---|
| ① 수신거부 | "수신거부", "그만", "빼주세요" | ⚫ 즉시 | **최우선 판정**. 억제 리스트 등록 + 설득 없는 확인, `언론홍보/수신거부` |
| ② 게재 통보 | "기사 나갔", "실렸", 링크 | 🟢 | 감사 + 인용 정확성 점검 1줄 + 성과 집계 |
| ③ 인터뷰 요청 | "인터뷰", "통화 가능", "일정" | 🔴 즉시 | 일정 3안 + 대표 연결 |
| ④ 자료 요청 | "고화질", "추가 자료", "매출 자료" | 🔴 즉시 | **약속한 자료만** 정확히 |
| ⑤ 부정/컴플레인 | 사실오류 지적, 항의, 정정 요구 | 🔴 신중 | 방어 금지. **에스컬레이션 플래그** |
| ⑥ 확인 질문 | "맞나요", "근거", "출처", "수치" | 🟠 당일 | 아래 5개 하위 유형으로 다시 나눈다 |
| ⑦ 보류/거절 | "이번엔 어렵", "다음 기회" | 🟢 | 정중히 수용. **자동 재접근 금지** |

**수신거부는 항상 최우선이다.** 다른 유형 신호와 함께 있어도 수신거부로 판정하고,
억제 등록은 분류 경로와 무관하게 서버가 강제한다. 어떤 모델 판단도 이걸 뒤집지 못한다.
어디에도 걸리지 않으면 **확인 질문(당일 응대)** 으로 안전하게 분류한다.

## ⑥ 확인 질문 — 5개 하위 유형

질문의 종류에 따라 답변의 위험도가 완전히 다르다. 먼저 어느 쪽인지 정한다.

| 하위 유형 | 기자가 실제로 묻는 것 | 답변 원칙 |
|---|---|---|
| **수치 검증** | "그 숫자 맞나요? 근거는?" | 값 + **산출 방식(기간·모수·기준)** + 출처. 셋 다 없으면 답하지 말고 확인 후 회신 |
| **경쟁사 비교** | "A사보다 낫다는 건가요?" | 타사를 평가하지 않는다. **자사 사실만** 말하고 비교는 기자 판단에 맡긴다 |
| **전략 의도** | "왜 지금 이걸 했나요?" | 공개 가능한 의사결정 배경만. 미공개 계획을 흘리지 않는다 |
| **향후 계획** | "다음은 뭔가요? 언제?" | 확정된 것만 시점과 함께. 미확정은 "확정되면 가장 먼저 알려드리겠습니다" |
| **부정적 맥락** | "이건 ○○ 논란 아닌가요?" | 회피·반박 금지. 사실관계만 짧게 + 필요하면 확인 후 회신. **즉답을 서두르지 않는다** |

**부정적 맥락 질문은 컴플레인 직전 단계**라서 컴플레인(⑤)과 동일하게 **에스컬레이션 대상**으로 표시한다.
자동 답변으로 넘기지 않고 담당자가 확인한 뒤 회신한다.

## 답장 초안 3단 스캐폴드

확인 질문(⑥)과 컴플레인(⑤)에는 초안을 **3단으로** 만든다. 사실은 사용자가 채우고,
스킬은 **빈칸이 있는 틀**을 준다. **빈칸을 추정으로 메우지 않는다.**

```
[공식 답변]
  · (확인된 사실을 한 문장으로)
  · (근거: 출처·기준·시점)

[대체 표현 — 상황에 맞게 하나 고르세요]
  · (하위 유형에 맞는 표현 2개)

[이렇게는 말하지 않기]      ← Do Not Say
  · (이 답변에서 절대 쓰면 안 되는 표현·주장)
```

**Do Not Say에 기본으로 들어가는 것**

- 확인되지 않은 수치·시점·계약 상대방
- 타사를 깎아내리는 평가("A사는 ~하지 못한다")
- 근거 없는 최상급·'최초'·'100%'·'절대' 류
- 미확정 계획을 확정처럼 말하기
- 기자의 질문 전제를 인정하는 말버릇("말씀하신 논란은…")

## 유형별 응대 포인트

- **① 수신거부** — 변명·설득·과한 사과 없이 즉시 수용하고 끝낸다.
  `기자님, 알겠습니다. 명단에서 즉시 제외했습니다. 좋은 하루 보내세요.`
  → 억제 리스트 등록 + `언론홍보/수신거부` 라벨. **재발송 시도 절대 금지.**
- **② 게재 통보** — 진심 어린 감사 1회. 여기에 **인용 정확성 점검 한 줄**을 더한다:
  기사에 인용된 수치·직책·회사명이 우리가 보낸 자료와 같은지 확인하고, 다르면 정정 요청이 아니라
  **정확한 자료를 다시 보내는 방식**으로 접근한다.
- **③ 인터뷰** — 일정 3안 + 방식(대면/화상/서면)을 열어 둔다. 사전 자료를 먼저 제안하면 밀도가 올라간다.
- **④ 자료 요청** — **원래 메일에서 링크로 약속한 자료만** 보낸다. 요청하지 않은 홍보자료를
  끼워 넣지 않는다. 약속한 적 없는 자료를 새로 요구받으면 준비 가능 여부를 먼저 답한다.
- **⑤ 컴플레인** — 방어·감정 대응 금지. 즉답이 어려우면 확인 절차와 회신 시한을 먼저 약속하고
  그때까지 인용 보류를 정중히 요청한다. **모든 컴플레인은 에스컬레이션 대상으로 표시**하고
  사람이 확인한 뒤 회신한다. 스킬이 단독으로 사실관계를 판단하지 않는다.
- **⑦ 보류/거절** — 한 번 감사하고 끝낸다. 미디어킷 링크 정도만 남긴다.
  **자동으로 다시 접근하지 않는다.** 다음 소식 때 연락해도 되는지 물어보는 선까지가 최대다.

## 응대 스타일

존댓말·간결·담백. 이모지·과한 감탄사 금지. "감사합니다"는 진심으로 1회.
회신 끝에 다음 관계의 여지를 남긴다.

## 절대 하지 말 것

- 실명·이메일 화면 노출
- 수신거부 요청에 재발송·설득
- 사실오류 지적에 방어 대응 / 사람 확인 없이 컴플레인 종결
- 확인 안 된 수치·계획을 답장에 채워 넣기(빈칸으로 남기고 사용자에게 묻는다)
- 타사 평가·비교 발언
- 인터뷰·자료 요청 24시간 초과 방치
