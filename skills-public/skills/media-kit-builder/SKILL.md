# 프레스킷 빌더 (media-kit-builder)

> **좋은 프레스킷은 소개서 PDF 한 개가 아니라, 기자가 기사 작성에 필요한 텍스트·시각 자산을
> 검색하고 내려받을 수 있는 허브다.**

이 한 줄이 이 스킬의 설계 철학이다. "파일 하나 만들기"가 아니라 **찾을 수 있게 만들기**가 목표다.
사용자를 인터뷰하듯 **한 번에 한 가지만** 물어 빈칸을 채운다. 소상공인도 30분 안에 완성한다.

> **규범 정본은 `convex/lib/pressGuide.ts`다** — `PRESS_KIT_SECTIONS`, `PRESS_KIT_CHECKLIST`,
> `ASSET_POLICY_ITEMS`, `GEO_ASSET_RULES`, `PRESS_KIT_PHILOSOPHY`, `WRITING_RULES`.
> 이 문서의 목차·체크리스트·수치는 그 상수의 문서 뷰이며, 값이 어긋나면 **코드가 맞다.**
> 상수를 고칠 때 이 문서를 같은 PR에서 갱신한다.

## 진행 원칙

1. **한 번에 질문 하나.** 답하기 쉽게 예시를 곁들인다.
2. **모르면 대신 초안을 써준다.** "이렇게 써봤는데 맞나요?"로 확인받는다.
3. **숫자는 근거·기준 시점을 함께 기록한다.** 확인이 안 되면 값을 만들지 말고 `[확인 필요]`로 남긴다.
4. 항목이 끝날 때마다 진행률을 보여준다(예: 4/10).
5. 완성 후 조립 → 검수 → 산출.

## 10개 항목 (수집 순서)

### ① 한 문장 회사 정의 + 80~120자 요약
- 질문: "회사를 처음 듣는 사람에게 **한 문장**으로 설명한다면?"
- 한 문장 정의와 80~120자 요약을 **따로** 받는다. 기자는 리드에 한 문장을, 박스 기사에 요약을 쓴다.
- 체크: 무엇을 하는 회사인지 + 규모/시점 숫자 1개.

### ② 회사 개요 — 설립연도·본사·시장·핵심 수치
- 표로 정리한다. 각 수치에 기준 시점 필수.

### ③ 창업 배경과 주요 연혁
- 질문 순서: "왜 시작했나요?" → "어떤 문제를 푸나요?" → "지금까지 무슨 일이 있었나요?"
- 연혁은 연도 + 한 줄. 자화자찬 문장이 아니라 **사건**을 적는다.

### ④ 대표 제품·서비스 설명
- 무엇을·누구에게·어떻게 다른지. 스펙은 문장이 아니라 **표나 불릿**으로(AI 인용 확률이 올라간다).

### ⑤ 창업자·경영진 약력과 고해상도 인물 사진
- 이름·직함·경력 3줄·인터뷰 가능 주제·바로 인용 가능한 코멘트 2개.
- 사진은 고해상도 원본 링크로. 저해상도 캡처는 기사에 못 쓴다.

### ⑥ 로고·제품 사진·스크린샷·영상 B-roll
- 로고(배경 투명 PNG, 가로/세로), 제품 사진, 스크린샷, 인포그래픽, 영상 소스.
- **파일명·Alt·캡션 규칙은 아래 「비주얼 자산 3대 규칙」을 반드시 적용한다.**

### ⑦ 최근 보도자료와 주요 언론 보도
- 최근 보도자료 링크 + 주요 매체 게재 목록(매체·날짜·제목·링크).
- 기자는 "이 회사가 전에 어떻게 다뤄졌는지"를 먼저 확인한다. 비어 있으면 신뢰가 깎인다.

### ⑧ 표준 회사 소개문(보일러플레이트)
- **80~120단어(100단어 안팎).**
- ⚠️ **보도자료 하단 보일러플레이트와 같은 문장이어야 한다** — 단일 소스로 관리한다.
  두 곳이 다르면 기자가 어느 쪽을 인용해야 할지 모른다.

### ⑨ 자산 사용 규정과 사진 크레딧 (필수)
아래 4항을 **모두** 명시한다. 하나라도 비면 기자가 이미지 사용을 포기하거나, 임의로 변형한다.
1. 사용 허용 범위(보도 목적 한정 여부)
2. 수정·변형 금지 사항(로고 비율·색상 변경 등)
3. 저작권·크레딧 표기 방법
4. 상표 사용 제한 및 추가 자산 문의처

### ⑩ 언론 문의 담당자·이메일·전화번호
- 실제로 받는 창구 하나. 응대 가능 시간도 함께.
- 마감에 쫓기는 기자는 연결이 안 되면 그냥 회사를 뺀다.

## 비주얼 자산 3대 규칙 (보도자료와 공통)

| 항목 | 규칙 |
|---|---|
| 파일명 | `[기업명]-[제품명]-[핵심키워드].png` |
| 나쁜 예 | `KakaoTalk_2026….jpg`, `스크린샷.png` |
| Alt | 주관적 수식어 없이 누가·무엇을 나타내는 이미지인지 **단문으로** 기술 |
| 캡션 | 이미지 **바로 아래 1줄**, 본문 핵심 키워드와 일치시킨다 |

파일명은 기자가 폴더에서 찾을 때, Alt·캡션은 생성형 AI가 이미지를 인용할 때 쓰인다.
"허브"가 되려면 이 셋이 갖춰져야 한다.

## 검수 체크리스트 (산출 직전)

- [ ] 제목에 회사명·행동·핵심 결과가 들어갔는가
- [ ] 첫 문단에 누가·무엇을·언제·어디서·왜·어떻게가 압축됐는가
- [ ] 과장 표현 대신 검증 가능한 숫자·출처가 있는가
- [ ] 인용문이 새 정보나 판단을 더하는가
- [ ] 회사 소개문이 100단어 안팎으로 표준화됐는가
- [ ] 기자가 바로 쓸 수 있는 원본 이미지와 캡션이 있는가
- [ ] 로고·사진의 사용 조건과 크레딧이 명확한가
- [ ] 담당자 이름·이메일·전화번호가 실제로 작동하는가
- [ ] 모바일에서도 문서와 다운로드 링크가 잘 열리는가
- [ ] 배포 전 고유명사·날짜·수치·링크를 교차 검증했는가

추가로: **`[확인 필요]`가 남아 있으면 미완성이다.** 크랩피치 웹앱의 완성도 점수도
placeholder가 든 필드를 미완성으로 계산한다 — 숫자를 채우기 위해 값을 지어내지 않는다.

## 산출 (사용자 선택)

- 문서(.md/.docx) · PDF · 웹 프레스킷(HTML 링크) · 보일러플레이트 스니펫
- 완성 후 `press-release-writer`(보일러플레이트·팩트 재사용) → `journalist-outreach`(배포 메일의 자료 링크)로 넘긴다.

## (선택) OpenCrab 지식 팩 참고

OpenCrab MCP가 연결돼 있으면 프레스킷 사례를 참고 자료로 조회할 수 있다. 단:

- `pr-agent/` 경로 문서는 **제외**한다(에이전트 실행 로그 성격의 노이즈).
- 팩에는 **합성 데모 데이터**가 섞여 있다 — 구조만 참고하고 **수치·인물·사건을 사실로 인용하지 않는다.**
- 팩 청크 임베딩이 갖춰지지 않은 구간이 있어 검색 리콜이 완전하지 않다. **조회는 보조 수단**이고,
  이 문서의 10항·체크리스트가 규범이다.

## AI 실행 원칙

크랩피치는 **공용 LLM 키를 제공하지 않는다.** 웹앱의 프레스킷 초안 생성·보강은 사용자 본인
키(BYOK)로 실행되며, 키가 없으면 해당 단계는 건너뛴다. AI가 만든 초안은 **폼에 채워질 뿐
자동 저장되지 않는다** — 저장은 항상 사용자가 한다.

## 절대 하지 말 것

- 한 번에 여러 질문 쏟기(사용자 이탈)
- 검증 안 된 숫자 삽입 — 모르면 `[확인 필요]`
- 근거 없는 최상급("업계 1위" 등). 근거가 있으면 조사기관·시점·모집단을 병기한다
- 자산 사용 규정(⑨) 없이 이미지만 올리기
- 보도자료와 프레스킷의 보일러플레이트를 다르게 쓰기
