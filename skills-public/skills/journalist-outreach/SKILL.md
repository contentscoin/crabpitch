# 기자 배포 오케스트레이터 (journalist-outreach)

보도자료(→ `press-release-writer`) 또는 아이디어를 받아 아래 5단계를 **순서대로, 사용자 확인을 받으며** 진행한다.

```
① 보도자료 확정 → ② 기자 매칭 → ③ 개인화 메일 초안 → ④ 동의·승인 게이트 → ⑤ Gmail '언론홍보' 발송·추적
```
절대 사용자 승인 없이 실제 메일을 발송하지 않는다. 기본 산출물은 항상 초안(draft)이다.

## 0. 시작 전 — 플랜 확인 (MCP 사용 시)

이 스킬의 CrabPitch 도구는 **MCP에서 유료 플랜 전용**이다. 먼저 `crabpitch_status`를 호출해
`skills`에 `journalist-outreach`가 있는지 본다.

- **있으면** 그대로 진행한다.
- **없으면**(무료 플랜) `crabpitch_match_journalists`·`crabpitch_email_template`는 호출해도
  막힌다. 사용자에게 이렇게 안내하고 **멈춘다**:

  > 채팅에서의 기자 매칭·메일 초안은 Solo 이상 플랜에서 열립니다.
  > **다만 이 기능은 CrabPitch 웹앱에서 무료 플랜으로도 지금 바로 쓸 수 있습니다** —
  > 웹앱에서 캠페인을 만들면 매칭·초안·승인·발송까지 그대로 진행됩니다.
  > 채팅에서 이어가고 싶으시면 설정에서 플랜을 올려 주세요.

**무료라고 해서 기능이 없는 게 아니라 창구가 웹앱이라는 점을 반드시 함께 말한다.**
막다른 길처럼 안내하면 사용자는 쓸 수 있는 기능을 포기한다.

MCP 없이 이 스킬만 쓰는 경우(도구 미연결)는 플랜과 무관하다 — 매칭 데이터가 없으므로
사용자가 직접 기자 목록을 주면 ③ 이후만 도와준다.

## ⛔ 두 가지 필수 원칙

**A. 기자 개인정보 비노출 (`docs/PRIVACY.md`)**
- 기자 **실명·이메일·연락처는 화면/응답/리스트/표에 절대 출력하지 않는다.**
  익명 코드(`기자 #A3F1`) + 매체 + beat + 신뢰도 + 적합도만 노출.
- 실제 이메일·실명은 **⑤ 실제 발송 시점**의 Gmail 수신자(To)·본문 인사말에만 주입한다.

**B. 컴플라이언스**
- 기자 데이터는 `mailing_status: candidate`(발송 미승인) 전제.
- 발송은 항상 **사용자 명시 승인** 후. 메일 하단에 **수신거부 문구** 필수.
- 동일 기자 **7일 내 재발송 금지**. 수신거부 회신은 **억제 리스트** 영구 등록(→ `reply-handler`).
- 발송은 **사용자 본인 Gmail(BYO-Email)**, Gmail **`언론홍보`** 라벨 안에서.

## ② 기자 매칭

주제 태그를 기자 온톨로지 쿼리로 변환한다.

**우선순위 (있는 도구부터):**
1. **CrabPitch MCP** (`docs/MCP-SETUP.md`, `cp_mcp_…` — 이 스킬의 도구는 Solo 이상)
   - `crabpitch_match_journalists` — 주제/태그로 후보 매칭. 응답은 **기자 코드·매체·beat·점수만** (실명·이메일 없음).
   - `crabpitch_email_template` — 피치 메일 제목/본문 템플릿.
   - `crabpitch_press_guide` — 보도자료 규범 조회 + 초안 규칙 검사.
   - `crabpitch_status` — 연결·플랜 확인.
2. **OpenCrab MCP** — `opencrab_query`(팩: `korean-journalist-contact-index-v2`)로 온톨로지 심 조회.
3. **미연결** — 사용자가 붙여넣은 리스트를 동일 스키마로 정규화.

매칭 후 실제 발송·실명 주입은 CrabPitch 웹앱 또는 아래 ⑤ Gmail 단계에서만 한다.

### 적합도 점수(0~100)
| 신호 | 배점 | 기준 |
|---|---|---|
| beat 일치 | 40 | 주제 ↔ beat_primary 정확 40 / 인접 25 |
| 최근 유사 기사 | 25 | top_reference가 유사 주제 |
| 기사 활동량 | 15 | reference_article_count |
| 연락처 신뢰도 | 15 | high 15 / medium 8 / low 3 (근거 개수만큼 가산) |
| 매체 급 | 5 | 타깃 독자 적합성 |
| **(감점) 신선도** | **−12까지** | 기자단 자료에서 30일 이상 확인되지 않으면 감점 |

**신선도 감점**은 이직·부서 이동 위험을 순위에 반영한다. 제외가 아니라 감점이다 —
경계값에서 갑자기 사라지는 것보다 낫다. 30일 이상 미확인 기자는 사용자에게 알린다.

**출력은 익명 코드로.** 예:
> **기자 #A3F1 · 지디넷코리아 · 플랫폼/핀테크 · 신뢰도 high — 87점**
> 이유: 최근 유사 투자유치 기사 다수, 투자 앵글 최적. (※ 실명/이메일 비표시)

`신뢰도 low`이거나 beat 불일치는 기본 제외.

## ③ 개인화 메일 초안 (7블록)
```
[제목]    25자, '사건'을 앞세우고 핵심 숫자 1개
[엠바고]  해제 시각이 있을 때만 최상단 1줄. 자료 블록에도 재고지(이중 표기)
[후킹]    그 기자의 최근 기사/beat 언급(무작위 발송 아님을 증명) — 실명은 쓰지 않고 기사/분야로
[핵심]    무엇 / 왜 뉴스 / 숫자 근거 (beat에 맞춰 재프레이밍)
[인용문]  대표 코멘트 1개(기사에 바로 인용 가능)
[자료]    보도자료·이미지·미디어킷 링크
[CTA+거부] 행동 요청 **정확히 1개** + 수신거부 문구(항상 마지막 블록)
```
- 초안 단계 본문은 인사말을 **"기자님"**으로(실명 미포함). 실명은 ⑤ 발송 시 주입.
- **CTA는 정확히 1개.** 2개 이상이면 서버 게이트에 걸려 발송이 차단된다.
  매체 유형별로 다르게: 방송→영상 소스·촬영 협조 / 뉴스와이어→원문·이미지 / 그 외→인터뷰 제안.
- **없는 자료를 약속하지 않는다.** 링크가 없으면 "준비해 보내드리겠습니다"로, 있을 때만
  "준비돼 있습니다"로 쓴다.
- **기사 인용은 발행일을 알 때만 날짜를 말한다.** 모르면 제목만 인용하고, 180일이 지났으면
  기사를 인용하지 않고 beat 기반 문구로 내린다 — 몇 달 전 기사를 "최근"이라 하면 역효과다.
- beat별 앵글 조정: 투자→라운드·성장률 / 제품→기능·차별점 / 유통→판매·트렌드 / 정책→사회적 의미.
- **완전 동일 메일 대량발송 금지.** 서버가 캠페인 내 메일의 개인화 구간을 서로 비교해
  전부 같으면 경고한다. 근거 기사가 없어 generic 문구로 폴백된 기자가 많다는 뜻이므로
  해당 기자를 빼거나 근거를 더 찾는다.

## ④ 동의·승인 게이트
발송 직전 사용자에게 보여주고 명시 확인:
1. 최종 수신자 수(코드로 표시, 개별 제외 가능)
2. 발송 통수 vs 한도(무료 월 10통 등)
3. 수신거부 문구 포함 여부
4. **초안 최소 1건을 사용자가 실제로 읽었는지** (아래 파일럿 게이트)
5. "Gmail 초안 생성 / 지금 발송(사용자 확인 후) / 취소"

### 파일럿 게이트 — 읽지 않은 캠페인은 나가지 않는다

초안이 **2건 이상인데 한 건도 확인하지 않았으면 캠페인 전체가 보류**된다. 웹앱에서
초안을 펼쳐 「이 초안 확인함」을 눌러야 풀린다. 즉시·예약·크론·Gmail 초안 생성 **네 경로
모두**에 걸린다.

전량 검토가 아니라 **1건**만 요구한다. 규칙 검사는 표현·수치·구조만 본다 —
"이 문장이 이 기자에게 말이 되는가"는 사람만 판정할 수 있고, 한 클릭에 수십 통이 나가는
구조에서 그 판정이 한 번도 없었던 것이 가장 비싼 사고다.

에이전트로 진행 중이라면 사용자에게 **초안 1건을 그대로 보여주고 확인을 받은 뒤** 다음으로
넘어간다. 1건짜리 캠페인은 면제된다(발송 버튼 자체가 그 초안을 본 행위다).

### 서버가 발송 시점에 다시 확인하는 것

승인했다고 다 나가지 않는다. 아래에 걸린 초안은 **삭제되지 않고 사유가 남은 채** 초안으로
유지된다. 사용자에게 제외 사유를 그대로 전달한다.

| 게이트 | 동작 |
|---|---|
| 수신거부 재대조 | 초안 생성 이후 수신거부한 기자를 제외 |
| 7일 쿨다운 | 같은 기자에게 7일 내 재발송 차단(사용자 단위 판정) |
| 표현 규정 | critical 1건이면 그 초안 차단 |
| 캠페인당 상한·월 한도 | 초과분은 이번 회차에서 제외 |

## ⑤ Gmail '언론홍보' 발송·추적 (`docs/GMAIL-SETUP.md`)
- 최초 1회 `mcp__Gmail__create_label`로 `언론홍보`(+하위) 생성.
- 기자별 `mcp__Gmail__create_draft`(수신자·본문에 실명/이메일 = **여기서만** 주입).
- `mcp__Gmail__label_thread`로 `언론홍보/발송` 부착.
- 실제 발송은 사용자 승인 후(자동 발송 도구 없음). 회신은 `reply-handler`가 `언론홍보`에서 모니터링.

## 절대 하지 말 것
- 실명·이메일·연락처 화면 노출 · 승인 없는 실발송 · 신뢰도 low 발송 · 7일 내 재발송 · 수신거부 문구 없는 메일 · 팩트체크 안 된 숫자
