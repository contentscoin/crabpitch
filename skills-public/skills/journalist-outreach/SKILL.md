# 기자 배포 오케스트레이터 (journalist-outreach)

보도자료(→ `press-release-writer`) 또는 아이디어를 받아 아래 5단계를 **순서대로, 사용자 확인을 받으며** 진행한다.

```
① 보도자료 확정 → ② 기자 매칭 → ③ 개인화 메일 초안(7블록) → ④ 게이트 + 승인 → ⑤ Gmail '언론홍보' 발송·추적
```

절대 사용자 승인 없이 실제 메일을 발송하지 않는다. 기본 산출물은 항상 초안(draft)이다.

> **규범 정본**
> · 메일 구조·CTA·엠바고·수신거부 문구 → `convex/lib/emailTemplate.ts`
> · 금칙어·수치 출처·최상급 판정 → `convex/lib/pressGuide.ts`
> · 발송 게이트 판정 → `convex/lib/emailCompliance.ts`
> · 7일 쿨다운·수신거부 재대조 → `convex/lib/sendGuard.ts`, `convex/drafts.ts`의 `finalizeCampaignSend`
> 값이 어긋나면 **코드가 맞다.** 코드를 고칠 때 이 문서를 같은 PR에서 갱신한다.

## ⛔ 두 가지 필수 원칙

**A. 기자 개인정보 비노출 (`docs/PRIVACY.md`)**
- 기자 **실명·이메일·연락처는 화면/응답/리스트/표·초안 어디에도 출력하지 않는다.**
  익명 코드(`기자 #A3F1`) + 매체 + beat + 신뢰도 + 적합도만 노출한다.
- 초안 본문의 인사말은 **"기자님,"** 으로 고정한다. 실명은 **⑤ 실제 발송 시점**의 Gmail
  수신자(To)와 본문 인사말에만 주입한다(웹앱에서는 `personalizeForSend`가 이 앵커를 찾아 주입한다).
- MCP 도구 응답에도 실명·이메일은 포함되지 않는다.

**B. 컴플라이언스 — 규범이 아니라 서버가 강제하는 것들**
- 기자 데이터는 `mailing_status: candidate`(발송 미승인) 전제.
- 발송은 항상 **사용자 명시 승인** 후, **사용자 본인 Gmail(BYO-Email)** 로만 나간다.
- 모든 메일에 **수신거부 문구**가 들어간다. 없으면 발송이 차단된다.
- 동일 기자 **7일 내 재발송 금지**, **캠페인당 발송 통수 상한** — 아래 ④ 참조.
- 수신거부 회신은 **억제 리스트 영구 등록**(→ `reply-handler`).

## ② 기자 매칭

주제 태그를 기자 온톨로지 쿼리로 변환한다.

**우선순위 (있는 도구부터)**
1. **CrabPitch MCP** (`docs/MCP-SETUP.md`, 유료 `cp_mcp_…` 키)
   - `crabpitch_match_journalists` — 주제/태그로 후보 매칭. 응답은 **기자 코드·매체·beat·점수만**.
   - `crabpitch_email_template` — 피치 메일 제목/본문 템플릿.
   - `crabpitch_status` — 연결·플랜 확인.
2. **OpenCrab MCP** — 기자 온톨로지 팩 조회.
3. **미연결** — 사용자가 붙여넣은 리스트를 동일 스키마로 정규화.

### 적합도 점수(0~100)

| 신호 | 배점 | 기준 |
|---|---|---|
| beat 일치 | 40 | 주제 ↔ beat_primary 정확 40 / 인접 25 |
| 최근 유사 기사 | 25 | 근거 기사가 유사 주제 |
| 기사 활동량 | 15 | 근거 기사 건수 |
| 연락처 신뢰도 | 15 | high 15 / medium 8 / low 3 |
| 매체 급 | 5 | 타깃 독자 적합성 |

**출력은 익명 코드로.** 예:
> **기자 #A3F1 · ○○일보 · 플랫폼/핀테크 · 신뢰도 high — 87점**
> 이유: 최근 유사 투자유치 기사 다수, 투자 앵글 최적. (※ 실명/이메일 비표시)

`신뢰도 low`이거나 beat 불일치는 기본 제외.
데이터 확인이 오래된 기자에게는 "팩 최종 확인 N일 경과" 표시가 붙는다 — 이직·퇴사로 주소가
바뀌었을 수 있으니 경과일이 길면 제외를 권한다.

## ③ 개인화 메일 초안 — 7블록

```
[제목]      25자 안팎, '사건'을 앞세우고 핵심 숫자 1개
[엠바고]    embargoAt가 있을 때만 최상단 1줄
[후킹]      그 기자의 근거 기사를 날짜까지 인용 — "지난 M월 D일 '○○' 기사 잘 보았습니다"
[핵심]      무엇 / 왜 뉴스 / 숫자 근거 — beat에 맞춰 재프레이밍
[인용문]    대표 코멘트 1개(기사에 바로 인용 가능)
[자료]      실제로 있는 링크만. 엠바고가 있으면 여기서 한 번 더 고지
[CTA + 수신거부]  행동 요청 정확히 1개 + 수신거부 문구(항상 마지막 블록)
```

**후킹 규칙**
- 캠페인 주제 태그와 겹치는 기사를 우선 고르고, 없으면 최신 기사를 쓴다.
- **180일을 넘긴 기사는 인용하지 않는다** — 날짜·제목 인용을 버리고 beat 기반 generic 후킹으로 강등한다.
  ("최근 기사 잘 봤습니다"가 반년 전 기사를 가리키면 역효과다.)
- 발행일을 모르면 날짜를 주장하지 않고 제목만 인용한다.
- 후킹이 없으면 스팸으로 분류된다. generic 폴백이라도 반드시 넣는다.

**CTA는 정확히 1개** — 매체 유형에 따라 갈린다(정본 매핑은 `convex/lib/packSync.ts`의 naver_oid 표).

| 매체 유형 | CTA 방향 |
|---|---|
| 뉴스통신사 | 원문 자료·이미지 즉시 송부 제안 |
| IT 전문지 | 기술 구조·실측 데이터 제공 제안 |
| 경제지 | 재무·성장 지표 상세 자료 제공 제안 |
| 그 외·미등록 | 대표 인터뷰 제안(기본값) |

미등록 매체는 기본값으로 폴백한다. **"매체별 완전 분기"로 과장하지 않는다** — 확인된 매체만 분기한다.
요청이 둘 이상이면 회신율이 떨어진다. 게이트도 CTA 중복을 잡는다.

**엠바고는 이중 표기** — 최상단 1줄 + 자료 블록의 "엠바고 해제 시각 이후 사용 가능" 재고지.
한쪽만 있으면 기자가 놓친다.

**분량** 공백 제외 600~800자(150~200단어 근사)를 권장한다. 초과는 **경고일 뿐 차단하지 않는다**(근사 환산이라).

### 템플릿 프리셋·커스텀 템플릿

| 프리셋 | 성격 |
|---|---|
| `standard` | 기본 7블록 |
| `data` | 수치를 팩트시트로 먼저 — 투자·실적·지표 |
| `story` | 문제→해결 서사 — 창업 스토리·신제품 배경 |
| `brief` | 4~5줄 초간결 — 바쁜 출입처·속보성 |

**프리셋과 커스텀 템플릿도 컴플라이언스 요소를 그대로 승계한다**: 엠바고 최상단 표기 ·
CTA 정확히 1개 · 수신거부 최종 블록 · 후킹 신선도 강등. 본문 구조만 다를 뿐 규칙은 같다.

커스텀 템플릿은 `{{엠바고}}` `{{매체CTA}}` `{{후킹}}` `{{최근기사}}` `{{수신거부}}` 등 자리표시자를 쓴다.
사용자가 수신거부·호칭을 빼도 **렌더링 시 자동 보정**되고, 개인화 자리표시자가 하나도 없으면
후킹이 자동 삽입된다(전 기자 동일 본문 = 대량발송을 막기 위해서다).

## ④ 게이트 + 승인

승인 화면에서 사용자에게 보여줄 것:

1. 최종 수신자 수(익명 코드로 표시, 개별 제외 가능)
2. 발송 통수 vs **월 한도**와 **캠페인당 상한**
3. 컴플라이언스 판정 결과(아래)와 쿨다운 제외 사유
4. "Gmail 초안 생성 / 예약 발송 / 지금 발송(사용자 확인 후) / 취소"

**컴플라이언스 게이트** (금칙어·수치 출처 상수는 보도자료와 공유, 판정만 다르다)

| 조건 | 판정 | 결과 |
|---|---|---|
| critical ≥ 1 | **FAIL** | **발송 차단.** 초안은 지우지 않고 사유를 기록한다 |
| high ≥ 3 또는 medium ≥ 5 | WARN | 승인 화면에 표시, 사용자가 확인 후 진행 가능 |
| 그 외 | pass | 진행 |

critical에 해당하는 것: 실행 가능한 **수신거부 안내 누락**, 근거 없는 '최초', '100%', '절대 보장'류.
보도자료 lint는 warn-only인데 메일만 차단하는 이유는 **발송이 되돌릴 수 없는 행위**여서다.

**서버가 강제하는 것 — 문서 규범이 아니라 코드가 막는다**

발송 확정은 **3경로**(즉시 발송 · 예약 발송 · 크론 백업)가 있고, 셋 모두 같은 공통 함수를 지난다.
그 함수가 순서대로 다시 검사한다:

1. **수신거부 재대조** — 초안 생성 후 수신거부한 기자는 여기서 걸러진다
2. **7일 쿨다운** — 캠페인과 무관하게, 같은 기자에게 7일 이내 발송 이력이 있으면 제외
   (판정은 **사용자 본인의 발송 이력만** 본다. 다른 사용자의 이력은 판정에도 표시에도 쓰지 않는다)
3. **컴플라이언스 critical FAIL 차단**
4. **캠페인당 발송 통수 상한** 재검증
5. **월 발송 한도** 재검증

제외된 초안은 **삭제하지 않고** 사유(예: "최근 7일 이내 발송 이력 — N일 후 발송 가능")를 남긴다.
따라서 "7일 규칙을 지켜주세요"라고 안내만 하지 말고, **막힌 이유를 사용자에게 설명**하면 된다.

## ⑤ Gmail '언론홍보' 발송·추적 (`docs/GMAIL-SETUP.md`)

- 최초 1회 `mcp__Gmail__create_label`로 `언론홍보`(+하위) 생성.
- 기자별 `mcp__Gmail__create_draft` — 수신자·본문 실명은 **여기서만** 주입.
- `mcp__Gmail__label_thread`로 `언론홍보/발송` 부착.
- 실제 발송은 사용자 승인 후. 회신은 `reply-handler`가 `언론홍보`에서 모니터링한다.

## 팔로업 (권장 — 자체 표준)

무응답 기자 재접촉 기준은 **지식 팩에 근거가 없다.** 아래는 크랩피치 자체 표준이며 **권장 사항**이다.

- 무회신 **7일** 경과 후에만
- **새 정보 1개**가 있을 때만(같은 내용 재전송 금지)
- 이전 메일 **복붙 금지** — 새 정보를 앞세운 초단문으로
- 쿨다운·상한·게이트는 팔로업에도 동일하게 서버에서 적용된다

## AI 개인화 (BYOK)

크랩피치는 **공용 LLM 키를 제공하지 않는다.** 메일 개인화는 사용자 본인 키(BYOK) 또는 본인 챗에서
실행되며, 키가 없으면 템플릿 초안 그대로 진행한다. AI 출력이 게이트에서 critical을 받으면
**템플릿 원본으로 되돌린다** — 개인화 때문에 컴플라이언스가 무너지지 않는다.

## 절대 하지 말 것

- 실명·이메일·연락처 화면 노출 · 초안에 실명 저장
- 승인 없는 실발송 · 신뢰도 low 발송
- 7일 내 재발송, 캠페인당 상한 우회 시도(서버가 차단한다)
- 수신거부 문구 없는 메일 · CTA 2개 이상
- 180일 넘은 기사를 "최근 기사"로 인용
- 팩트체크 안 된 숫자, 출처 없는 수치
