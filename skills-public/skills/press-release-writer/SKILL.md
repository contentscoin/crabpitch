# 보도문 작성 (press-release-writer)

기자는 하루 수백 통을 받는다. 첫 문단에서 "이건 기사가 된다"가 보여야 한다.
이 스킬은 사용자 입력을 표준 보도자료로 조립한다.

## 먼저 확보할 것 (없으면 한 번에 하나씩 질문)

- **핵심 한 줄(헤드라인 후보)**: 무슨 일이 일어났나?
- **주체**: 회사/브랜드/인물명
- **언제·어디서**
- **뉴스 밸류**: 최초/최대/최고/투자/수상/사회적 의미 중 무엇인가
- **숫자·근거**: 투자액·매출·이용자 수·성장률 (팩트체크 가능해야 함)
- **인용문**: 대표/관계자 코멘트 1개
- **자료 링크**: 이미지·미디어킷
- **주제 태그**: 예) IT·스타트업, 투자, 유통, F&B, 뷰티, 정책

## 작성 규칙

**구조 = 역피라미드**
1. 1문단: 5W1H 요약(결론·숫자 먼저)
2. 2문단: 배경·근거
3. 3문단: 의미·전망 + 인용문
4. 하단: 보일러플레이트(회사 한 줄 소개) — 있으면 첨부

**헤드라인 3안**
- 25자 안팎, 회사명보다 '사건'을 앞세운다. 핵심 숫자 1개 포함.
- 톤을 다르게: (a) 사실형 (b) 성과·숫자 강조형 (c) 의미·트렌드형

**문장**
- 형용사·최상급 남발 금지("업계 1위" 등은 근거 없으면 삭제).
- 검증 안 된 숫자 삽입 금지. 숫자는 기준 시점 명시.
- **검증할 수 없는 숫자는 지어내지 말고 `[확인 필요]`로 남긴다.** 배포본에 이 표기가
  남아 있으면 그 자체로 위반이다.

## 규칙 검사 (CrabPitch MCP 연결 시)

`crabpitch_press_guide`에 `draft`·`title`을 넘기면 결정적 규칙 검사 결과가 돌아온다.
LLM 판단이 아니라 코드 검사라 근거를 그대로 사용자에게 보여줄 수 있다.

- `section`으로 규범만 조회할 수도 있다: `structure` · `writing` · `geo` · `adlaw` · `presskit`
- **미디어킷이 있으면 `boilerplate`와 `factSheet`를 함께 넘긴다.** 그래야 아래 두 검사가 돈다.

| 검사 | 내용 |
|---|---|
| L1 금칙어 | 근거 없는 "업계/세계 최초", "100%", "절대 보장" 등 — critical |
| L2 최상급 | 무출처 순위·최상급. 같은 문장에 출처가 있으면 통과 |
| L4 수치-출처 | 정량 표현 인근에 기관·연도·집계 기준이 없으면 위반 |
| 보일러플레이트 | 미디어킷 원문과 다르면 **사본 표류**로 잡는다 |
| 수치 대조 | 본문 수치가 팩트시트에 없으면 지적 |

**보일러플레이트는 미디어킷이 단일 소스다.** 배포본마다 조금씩 고쳐 쓰면 설립연도·직원 수가
릴리스마다 갈리고, 기자가 과거 기사와 대조하는 순간 신뢰를 잃는다. 내용을 바꿔야 하면
미디어킷을 먼저 고치고 다시 불러온다.

검사 결과는 **참고 신호**다(1차는 경고 전용이라 작성을 막지 않는다). 다만 critical은
사용자에게 반드시 알리고 고쳐 쓴다.

**MCP가 없을 때**는 `references/`의 규범 요약을 읽고 직접 대조한다 —
[`structure.md`](./references/structure.md) · [`geo.md`](./references/geo.md) ·
[`compliance.md`](./references/compliance.md).
정본은 항상 서버 코드이므로, 값이 어긋나면 `crabpitch_press_guide` 결과가 맞다.
