# 표준 구조 · 작성 전략 수치

> 정본은 **`convex/lib/pressGuide.ts`** — `PRESS_STRUCTURE`, `WRITING_RULES`,
> `CRABPITCH_FORM_BODY_CHARS`, `NAMING_CONSISTENCY_RULES`.
> 값이 어긋나면 코드가 맞다. 상수를 고칠 때 이 파일을 같은 PR에서 갱신한다.

## 표준 구조

| # | 블록 | 분량 | 목적 |
|---|---|---|---|
| 1 | 제목 | 30자 이내 | 핵심 가치 전달 |
| 2 | 부제 | 2개, 각 40자 이내 | 제목이 못 담은 보조 포인트 |
| 3 | 리드 | **정확히 3문장** | 5W1H 집약 — ①발표 사실 ②배경·차별점 ③기대효과·다음 스텝 |
| 4 | 바디 1 | 2~3문단 + 소제목(H3) 1개 | 핵심 발표 내용 상세 |
| 5 | 바디 2 | 2~3문단 + 소제목(H3) 1개 | 배경·차별점·업계 맥락 |
| 6 | 바디 3 (선택) | 1~2문단 | 기대 효과·향후 계획 |
| 7 | 임원 코멘트 | 1~2개, 각 1~2문장 | 실명·직책 명시. 제목을 반복하지 않고 결정 이유·시장 해석·향후 계획 중 1개를 더한다 |
| 8 | 회사 소개(보일러플레이트) | 80~120단어(100단어 안팎) | 표준 회사 소개문 — **프레스킷과 단일 소스** |
| 9 | 미디어 문의 | 1줄 | 담당자·이메일·전화번호 |

**바디는 2~3개 가변이다.** 지식 팩 안에서도 바디 개수 표기가 문서마다 달라(2개 목록 / 3개 템플릿),
양쪽과 모순되지 않도록 가변으로 둔다. 소식이 단순하면 2개, 배경 설명이 필요하면 3개.

## 작성 전략 수치

| 항목 | 값 | 비고 |
|---|---|---|
| 리드 문장 수 | 3 | 5W1H를 리드에서 끝낸다 |
| 문장 길이 | 50자 지향 / **80자 상한** | 초과하면 문장을 쪼갠다 |
| 한 문단 문장 수 | 4문장 이내 | 문단만 떼어 읽어도 의미가 완결돼야 한다 |
| 수동태 비율 | 20% 미만 | |
| 핵심 메시지 | 3개 이내 | 더 많으면 아무것도 안 남는다 |
| 임원 코멘트 | 1~2개 | 실명·직책 필수 |
| 보일러플레이트 | 80~120단어 | 미디어킷과 같은 문장 |
| 피칭 이메일 본문 | 150~200단어 | 보도자료가 아니라 **배포 메일** 기준 → `journalist-outreach` |
| 검증 불가 수치 | `[확인 필요]` | 창작 금지. 배포본에 잔존하면 위반 |

### 크랩피치 웹 폼 본문 규격 (팩 근거 아님)

크랩피치 캠페인 폼의 보도자료 본문은 **300~500자**다. 이는 폼의 기존 산출 규격이며
지식 팩에서 온 값이 아니다(`CRABPITCH_FORM_BODY_CHARS`). 팩 개정 시 재대조 대상에서 제외한다.
폼 경로에서는 리드 → 배경 → 인용 → 보일러플레이트 순서만 지키고, 9블록 풀 템플릿은 쓰지 않는다.

## 표기 일관성 (범용 원칙만)

지식 팩의 스타일북 레벨은 어휘가 사실상 전부 특정 기업 고유 상수여서 **이식하지 않았다.**
아래 범용 원칙만 적용하고, 실제 표기값은 사용자에게서 받는다.

- 회사명 표기를 띄어쓰기까지 통일하고, 영문 병기 규칙을 문서 전체에서 고정한다
- 제품·서비스명은 공식 표기를 유지한다
- 직책 표기 구조를 고정하고 약어를 쓰지 않는다
- 같은 값의 수치 표기를 혼용하지 않는다(병기 규칙을 문서 상단에 고정)

## 자주 나오는 실수

- 리드가 4문장 이상으로 늘어나며 5W1H가 바디로 밀림 → 리드에서 끝낸다
- 임원 코멘트가 제목을 그대로 반복 → 새 정보(결정 이유·시장 해석·향후 계획) 1개를 더한다
- 보일러플레이트를 보도자료마다 다시 씀 → 미디어킷의 것을 그대로 복사한다
- 소제목 없이 긴 줄글 → 검색 의도가 담긴 소제목으로 덩어리를 나눈다
