# GEO — 생성형 엔진 최적화

> 정본은 **`convex/lib/pressGuide.ts`** — `GEO_PHILOSOPHY`, `GEO_RULES`, `GEO_TARGETS`, `GEO_ASSET_RULES`.
> 값이 어긋나면 코드가 맞다. 상수를 고칠 때 이 파일을 같은 PR에서 갱신한다.

> **구조(Structure)가 곧 인용성(Citability)이다.**
> AI는 화려한 문장이 아니라 **검증 가능한 수치와 이해하기 쉬운 구조**를 인용한다.

## 12규칙

| 규칙 | 내용 |
|---|---|
| 첫 100단어의 법칙 | 헤드라인과 리드문(첫 100단어 이내)에 누가·무엇을·언제·구체적 수치를 모두 담는다 |
| Key Takeaways 배치 | 최상단에 **[3줄 요약]**을 불릿으로 배치한다 |
| 정보의 덩어리화(Chunking) | 섹션마다 검색 의도가 반영된 H2/H3 소제목을 단다. 줄글 나열 금지 |
| 구조화된 데이터 | 스펙·비교·장단점은 문장이 아니라 **표 또는 불릿**으로 |
| FAQ 꼬리말 | 본문 하단에 Q&A 섹션을 둔다 — 생성형 AI의 답변 출력 패턴과 형태를 맞춘다 |
| 의도 기반형 헤드라인 | 사실 나열이 아니라 **검색 질문·해결책 형태**로 제목을 설계한다 |
| One Idea Rule | 복문 대신 단문. 한 문단 3~4문장, 문단만 떼어 읽어도 의미가 완결돼야 한다 |
| 시맨틱 다양성 | 같은 키워드 반복은 스팸으로 인지될 수 있다. 문맥 기반 유의어를 쓴다 |
| 형용사 타파 → 수치 치환 | '혁신적인·최고의' 같은 홍보성 형용사를 배제하고 '처리 시간 30% 단축'처럼 검증 가능한 수치로 |
| 엔티티 표기 통일 | 회사명·제품명의 국·영문 표기를 띄어쓰기까지 통일한다(다중 객체 오인식 방지) |
| 사실 주장형 실명 코멘트 | '기쁘다·기대된다'식 소회 금지. 실명·직책 + 전문적 견해 |
| 교차 검증 링크 | 공신력 있는 외부 기관 통계를 함께 인용해 객관성을 확보한다 |

## 수치 목표

| 항목 | 값 |
|---|---|
| Key Takeaways | **3줄** |
| 핵심을 끝내야 하는 지점 | 첫 **100단어** |
| FAQ 문항 수 | **규정 없음** — 섹션 존재만 필수 |

⚠️ FAQ 문항 수를 임의로 만들지 않는다. 지식 팩에 규정이 없다(섹션이 있어야 한다는 것만 있다).
팩의 "기자 예상 Q&A 10~15개"는 보도자료 부록 Q&A이지 GEO 꼬리말이 아니다.
실제로 물어볼 질문만 쓰고, 채우기 위해 질문을 지어내지 않는다.

## 이미지 자산 규칙 (프레스킷과 공통)

| 항목 | 규칙 |
|---|---|
| 파일명 | `[기업명]-[제품명]-[핵심키워드].png` |
| 나쁜 예 | `KakaoTalk_2026….jpg`, `스크린샷.png` |
| Alt | 주관적 수식어 없이 누가·무엇을 나타내는 이미지인지 **단문으로** 기술 |
| 캡션 | 이미지 **바로 아래 1줄**, 본문 핵심 키워드와 일치시킨다 |

프레스킷 쪽 자산 관리(사용 규정·크레딧)는 `media-kit-builder` 스킬을 따른다.

## GEO 레이어를 얹는 순서

1. 표준 구조로 본문을 먼저 완성한다(구조 없이 GEO만 얹으면 형식만 남는다).
2. 최상단에 [3줄 요약]을 붙인다.
3. 바디마다 소제목을 검색 의도 형태로 다시 쓴다.
4. 스펙·비교 문장을 표/불릿으로 변환한다.
5. 형용사를 수치로 치환한다 — 치환할 수치가 없으면 **형용사를 삭제**한다(수치를 만들어 내지 않는다).
6. 하단에 FAQ를 붙인다.
7. 이미지 파일명·Alt·캡션을 위 규칙으로 정리한다.
