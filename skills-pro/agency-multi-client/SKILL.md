# 멀티 클라이언트 운영 (agency-multi-client) — Agency

대행사의 리스크는 두 가지다: **클라이언트 간 섞임**(A사 자료가 B사 메일에), 그리고
**기자 피로**(같은 대행사가 한 기자를 여러 클라이언트로 두드림). 이 스킬은 둘 다 구조로 막는다.

## ⛔ 원칙
- PII 원칙 동일: 기자는 코드+매체로만 표시(어느 클라이언트 화면에서든).
- **클라이언트 정보 격리**: 한 클라이언트의 미공개 정보(엠바고·숫자)를 다른 클라이언트
  맥락·메일·리포트에 절대 섞지 않는다.
- 발신 Gmail은 대행사 계정 — 수신거부는 **발신자 기준**이므로 억제 리스트는 전사 공통 적용.

## ① 클라이언트 온보딩

새 클라이언트마다 체크리스트로 확보:
1. 미디어킷(없으면 media-kit-builder 먼저) · 보일러플레이트 · 승인권자(이름·직책) · 금지어/공개 커트라인
2. Gmail 라벨 트리 생성(`mcp__Gmail__create_label`):
```
언론홍보/{클라이언트}/발송
언론홍보/{클라이언트}/회신
언론홍보/{클라이언트}/인터뷰
언론홍보/{클라이언트}/수신거부
언론홍보/{클라이언트}/캠페인/{캠페인명}   ← 캠페인 시작 시
```
3. 담당자 배정(팀 운영 시): 클라이언트별 담당 1명 + 백업 1명, 인수인계 노트 위치 합의.

## ② 억제 리스트 — 전사 공통 + 클라이언트별 이중 관리

| 리스트 | 트리거 | 효력 |
|---|---|---|
| **전사 공통** | 기자가 "수신거부/그만"(전면 거부) | 모든 클라이언트 발송에서 영구 제외 |
| 클라이언트별 | "이 회사 소식은 그만" / "이 업종 안 다룸" | 해당 클라이언트(또는 업종)만 제외 |

- 판단이 애매하면 **전사 공통으로** 등록한다(보수적 해석). 발신자가 같은 이상,
  기자 입장에선 "같은 곳에서 또 왔다"다.
- 수신거부 처리 자체는 reply-handler ⑥ 절차 그대로 + 위 분류만 추가.

## ③ 기자 피로도 관리 (이해충돌 포함)

발송 전 크로스체크 — 같은 기자 코드가 **최근 7일 내 다른 클라이언트 캠페인**에 포함됐는지 확인:
- 겹치면 후순위 클라이언트 발송에서 제외하거나 다음 주로 이월(7일 규칙은 발신자 기준으로 지킨다).
- **동종 업계 경쟁 클라이언트 2곳**을 대리하는 경우: 같은 기자에게 같은 주에 두 클라이언트를
  피치하지 않는다 + 양쪽에 상호 존재를 고지(계약 시). 엠바고·미공개 정보는 담당자 분리.
- 주간 발송 계획표(클라이언트×기자 코드 매트릭스)로 겹침을 사전에 본다.

## ④ 2단계 승인 게이트

press-distribution ④의 승인 게이트를 **두 번** 통과해야 발송 준비가 끝난다:
1. **클라이언트 승인** — 보도자료 최종본·수신자 수·발송 일정을 승인권자에게 확인(메일/메신저 기록 남김).
2. **발송 승인** — 대행사 담당자가 초안·수신거부 문구·한도(플랜 발송 통수)를 최종 확인.
클라이언트 승인 없는 발송은 어떤 경우에도 금지(사고의 90%가 여기서 난다).

## ⑤ 화이트라벨 주간 리포트

클라이언트마다 campaign-report를 실행해 주간 리포트로 묶는다:
- 표지: **대행사 브랜딩**(CrabPitch 표기 제거 가능 — 화이트라벨), 클라이언트명, 기간.
- 본문: KPI 카드 · 게재 목록 · 회신 하이라이트(기자 코드) · 다음 주 계획.
- 클라이언트에게도 기자 실명·이메일은 제공하지 않는다 — 코드+매체로 충분하며,
  기자 관계·연락처는 대행사의 자산이자 보호 의무다.
- 산출: 마크다운 기본, 요청 시 PDF/HTML(docx·pdf 스킬 연동).

## ⑥ 전사 현황판 (대행사 내부용)

"클라이언트별 현황" 요청 시:
```
클라이언트 | 진행 캠페인 | 이번 주 발송 | 회신 | 게재 | 다음 액션
──────────────────────────────────────────────
A사        | 시리즈B 발표 | 12통        | 3    | 1    | 팔로업 D+7 (금)
B사        | 신제품 출시  | 준비 중      | -    | -    | 클라이언트 승인 대기
합계(플랜 한도 대비): 발송 34/무제한 · 활성 캠페인 3
```

## 다른 스킬과의 연결
- 캠페인 실행은 클라이언트별로 **press-distribution** 그대로(라벨만 클라이언트 트리 사용)
- 리포트 엔진: **campaign-report** · 팔로업: **follow-up-scheduler** · 인터뷰: **interview-prep**

## 절대 하지 말 것
- 클라이언트 간 정보·자료 혼입 · 클라이언트 승인 없는 발송 · 같은 기자에 같은 주 복수 클라이언트 피치
- 전면 수신거부를 클라이언트별로 좁게 해석 · 클라이언트에게 기자 실명·이메일 제공
- 경쟁 클라이언트 상호 미고지 대리
