# 캠페인 성과 리포트 (campaign-report) — Solo 이상

배포는 발송이 아니라 **게재로 끝난다**. 이 스킬은 캠페인 하나를 골라
발송→회신→게재를 숫자로 집계하고, 다음 캠페인을 개선할 근거를 만든다.

## ⛔ PII 원칙 (무료 팩과 동일)
- 리포트의 기자 표기는 **익명 코드(`기자 #A3F1`) + 매체**만. 실명·이메일 출력 금지.
- 게재 기사는 공개물이므로 **기사 제목·매체·URL은 표기 가능**하되, 표의 기자 열은 코드로 유지.

## 집계 워크플로우

### ① 캠페인 선택 & 데이터 수집 (Gmail MCP)
1. `mcp__Gmail__list_labels`로 `언론홍보/캠페인/*`(Agency 모드: `언론홍보/{클라이언트}/캠페인/*`)
   라벨과 **라벨 ID**를 확인 → 사용자에게 대상 캠페인 확인.
2. `mcp__Gmail__search_threads` — ①에서 얻은 라벨 ID로 `label:{라벨ID}` 질의해 스레드 수집
   (`label:`은 표시명이 아닌 라벨 ID를 받으므로 `언론홍보/캠페인/{캠페인명}` 표시명을 그대로 넣지 말 것).
   - 스레드 수 = **발송 통수**, 상대 메시지가 달린 스레드 = **회신**.
3. 회신 스레드는 `mcp__Gmail__get_thread`로 열어 7유형(reply-handler 기준)으로 분류 집계.
   미분류 회신이 있으면 reply-handler를 먼저 돌리도록 안내.
   **CrabPitch MCP 연결 시** `crabpitch_classify`에 회신 본문을 넘겨 동일 7유형 분류를 받아도 된다.

**Gmail MCP 미연결 시**: 사용자가 붙여넣은 발송 기록/회신 요약을 입력으로 동일 집계.

### ② 게재 확인 (발송 D+3 / D+7 권장)
1. 웹 검색(WebSearch 등)으로 `"{회사명}"`, 헤드라인 핵심 키워드, `site:{매체 도메인}` 조합 검색.
2. 발견한 기사마다 기록: 매체 · 기사 제목 · URL · 게재일 · 논조(긍정/중립/이슈).
3. 게재 통보(④유형) 회신과 대조해 누락 없이 합산. 검색으로 못 찾은 매체는 "미확인"으로 남긴다
   (0건 단정 금지 — 포털 미전송 매체는 검색에 안 잡힐 수 있음).

### ③ KPI 계산
| 지표 | 계산 | 참고 범위(통설, 참고용) |
|---|---|---|
| 회신율 | 회신 스레드 ÷ 발송 통수 | 개인화 피치 5~15% / 비개인화 1~3% |
| 게재율 | 게재 기사 수 ÷ 발송 통수 | 초기 기업 5~10%면 양호 |
| 인터뷰 전환 | ①인터뷰 요청 수 ÷ 회신 수 | — |
| 수신거부율 | ⑥수신거부 ÷ 발송 통수 | 3% 초과 시 타깃팅 재점검 🔴 |

- 도달(리치) 추정은 **매체 방문자 공개 추정치**가 있을 때만, "추정·참고용" 딱지를 붙여 제시.
  근거 없는 도달 수치를 만들어내지 않는다.

## 리포트 산출 (마크다운, 요청 시 HTML/PDF)

```
[캠페인명 · 기간 · 보도자료 헤드라인]
KPI 카드: 발송 N통 · 회신율 x% · 게재 M건(게재율 y%) · 인터뷰 k건
게재 목록: 매체 | 기사 제목(링크) | 게재일 | 논조
회신 하이라이트: 기자 #코드 · 매체 · 유형 · 한 줄 요약
퍼널: 발송 → 회신 → 인터뷰/자료요청 → 게재
개선 제안 3가지 (아래 진단 규칙)
```

### 개선 제안 진단 규칙 (다음 캠페인용)
- **회신율 낮음(<3%)** → 제목·첫 문장 개인화 점검: 제목에 숫자 있었나, 첫 문장이 기자 최근
  기사를 언급했나(journalist-outreach-email 체크리스트 재실행).
- **회신 많은데 게재 적음** → 자료 부족 신호: 미디어킷·이미지 보강(media-kit-builder).
- **특정 beat만 무반응** → 매칭 재조정: 그 beat 제외 or 앵글 교체(press-distribution ②).
- **수신거부 3%+** → 타깃 과확장: 적합도 컷 상향(70점+만), 발송 통수 축소.
- 발송 요일·시간대별 회신 분포가 보이면 최적 시간대 제안(→ follow-up-scheduler와 연동).

## 기자 관계 스코어 (관계 CRM 시드)

캠페인이 끝날 때마다 기자 코드별 히스토리를 갱신해 다음 매칭에 반영한다.

| 이벤트 | 점수 |
|---|---|
| 게재(④) | +5 |
| 인터뷰/자료 요청(①②) | +3 |
| 확인 질문·보류(③⑤) | +1 |
| 무응답 | 0 |
| 수신거부(⑥) | 영구 제외(점수 없음) |

- 누적 스코어는 press-distribution 매칭 점수에 **관계 가점 최대 +10**으로 반영.
- 저장 형태: 사용자 노트/파일에 `기자코드, 매체, 누적점수, 최근접촉일` CSV — 실명·이메일 저장 금지.

## 다른 스킬과의 연결
- 무응답 기자 팔로업 → **follow-up-scheduler** (Growth+)
- 인터뷰 성사 건 준비 → **interview-prep**
- 경쟁사 대비 노출 비교를 리포트에 첨부 → **competitor-coverage** (Growth+)

## 절대 하지 말 것
- 기자 실명·이메일을 리포트에 출력 · 근거 없는 도달/조회수 창작 · 미확인 매체를 "게재 실패"로 단정
- 게재 기사 논조를 왜곡 요약 · 관계 스코어에 PII 저장
